Use TB2J with TBUpy +U Results
================================

This guide describes the full workflow for computing exchange parameters
from a TBUpy self-consistent tight-binding +U calculation.  The workflow is
useful when the starting Hamiltonian is non-spin-polarized, such as a
Wannier90 Hamiltonian, and spin splitting is generated by a TBUpy +U SCF
calculation before running TB2J.

Overview
--------

The data flow is::

   Wannier90 / HamiltonIO Hamiltonian
       -> TBUpy +U SCF
       -> .tbupy.nc converged result file
       -> TB2J exchange calculation

The dependency direction is important:

* HamiltonIO does not depend on TBUpy.
* TBUpy reads HamiltonIO-compatible Hamiltonians and owns the ``.tbupy.nc``
  file format.
* TB2J imports TBUpy only in the optional TBUpy interface.

The ``.tbupy.nc`` file stores the effective Hamiltonian after SCF,
``H_eff = H_0 + V_U`` with ``V_U`` embedded in the onsite ``R=(0,0,0)``
block.  It also stores the converged density matrix, Hubbard parameters,
double-counting type, Fermi level, structure, orbital metadata, and Wannier
centers when available.

Requirements
------------

Install TB2J, HamiltonIO, and TBUpy in the same Python environment.  In this
development workspace the environment is activated with::

   source /home/hexu/projects/myenvs/mydev/bin/activate

For user installations, make sure that ``import tbupy``, ``import HamiltonIO``
and ``import TB2J`` all work in the environment used for the calculation.

Step 1: Run TBUpy SCF and Save a Result File
--------------------------------------------

The example below uses LaMnO3 Wannier90 data, converts it to a spin-duplicated
HamiltonIO ``LCAOHamiltonian``, runs a collinear AFM TBUpy +U SCF calculation,
and writes a ``.tbupy.nc`` result file.

.. code-block:: python

   import sys
   from pathlib import Path

   import numpy as np
   from HamiltonIO.wannier import WannierHam
   from tbupy.model import TBUpyModel
   from tbupy.util import (
       LAMNO3_ORBITAL_METADATA,
       make_mn_spin_polarized_rho,
       wannier_to_lcao,
   )


   def make_kgrid(nk):
       kpts = np.array(
           [
               [i / nk[0], j / nk[1], k / nk[2]]
               for i in range(nk[0])
               for j in range(nk[1])
               for k in range(nk[2])
           ],
           dtype=float,
       )
       return kpts, np.ones(len(kpts)) / len(kpts)


   data_dir = Path("/path/to/LaMnO3_DMFT_data")
   output = Path("lamno3_u4p5_j1_kanamori_fllns_afm_k4.tbupy.nc")

   wham = WannierHam.read_from_wannier_dir(str(data_dir), "wannier90")
   ham = wannier_to_lcao(
       wham,
       orbital_metadata=LAMNO3_ORBITAL_METADATA,
       spin_mode="duplicate",
       nel=88,
   )

   model = TBUpyModel(
       ham,
       {"Mn": {"U": 4.5, "J": 1.0, "L": 2}},
       hubbard_type="kanamori",
       dc_type="FLL-ns",
       mixing="pulay",
       mixing_beta=0.3,
   )

   kpts, kweights = make_kgrid((4, 4, 4))
   rho_init = make_mn_spin_polarized_rho(
       model.basis_set,
       nel=88,
       moment=0.6,
       order="afm",
       noise_level=0.3,
       seed=0,
   )

   scf = model.run_scf(
       kpts,
       kweights,
       nel=88,
       width=0.1,
       max_iter=100,
       rho_init=rho_init,
       diag_only=False,
   )

   model.save_scf_result(
       output,
       scf,
       magnetic_order="afm",
       source="LaMnO3 Wannier90",
       scf_kmesh="4 4 4",
   )

   print("converged", scf.converged)
   print("iterations", scf.n_iterations)
   print("efermi", scf.efermi)
   print("result", output)

Important TBUpy choices:

* ``spin_mode="duplicate"`` creates a collinear spinful Hamiltonian from a
  non-spin-polarized Wannier Hamiltonian.
* ``hubbard_type="kanamori"`` or ``"liechtenstein"`` should be used when
  orbital splitting from explicit ``U`` and ``J`` is important.
* ``dc_type="FLL-ns"`` is the charge-only/non-spin-polarized double-counting
  choice used in the LaMnO3 tests described here.
* ``diag_only=False`` allows off-diagonal orbital polarization in the density
  matrix.
* ``noise_level`` seeds orbital symmetry breaking in the initial Mn d-shell
  density.  Use a fixed ``seed`` for reproducibility.
* A denser SCF k-mesh can change the converged solution.  For the LaMnO3 tests,
  ``4x4x4`` was needed to obtain the small-gap solutions reported below.

Step 2: Inspect the TBUpy Result
--------------------------------

TBUpy can load the saved result and return HamiltonIO-compatible models:

.. code-block:: python

   from tbupy.io import load_scf_result

   result = load_scf_result("lamno3_u4p5_j1_kanamori_fllns_afm_k4.tbupy.nc")

   # Spin-interleaved HamiltonIO-compatible model.
   hamiltonian = result.to_hamiltonio()

   # TB2J collinear representation: separate spin-up and spin-down models.
   model_up, model_dn = result.to_collinear_models()

   print(result.efermi)
   print(result.metadata)

The conversion to collinear models checks that spin-flip blocks are zero within
tolerance.  Non-collinear/SOC TBUpy results are not supported by this first
interface.

Step 3: Run TB2J from Python
----------------------------

The Python API is the primary interface:

.. code-block:: python

   from TB2J.interfaces.tbupy_interface import gen_exchange_tbupy

   gen_exchange_tbupy(
       tbupy_result_file="lamno3_u4p5_j1_kanamori_fllns_afm_k4.tbupy.nc",
       output_path="TB2J_lamno3_u4p5_j1",
       magnetic_elements=["Mn"],
       kmesh=[5, 5, 5],
       nz=40,
       Rcut=7.0,
       nproc=1,
   )

The TB2J interface loads TBUpy lazily.  If TBUpy is not installed, this
interface raises a clear optional-dependency error.  Normal TB2J and HamiltonIO
imports do not require TBUpy.

Step 4: Run TB2J from the Command Line
--------------------------------------

The command-line wrapper delegates to the same Python API:

.. code-block:: bash

   tbupy2J.py \
       --input lamno3_u4p5_j1_kanamori_fllns_afm_k4.tbupy.nc \
       --output_path TB2J_lamno3_u4p5_j1 \
       --kmesh 5 5 5 \
       --elements Mn \
       --nproc 1

The current CLI exposes the most common options.  For advanced settings, use
the Python API.

Step 5: Read the TB2J Output
----------------------------

TB2J writes the usual output directory, for example::

   TB2J_lamno3_u4p5_j1/
   ├── exchange.out
   ├── exchange_orb_decomposition.out
   ├── JvsR.pdf
   ├── TB2J.pickle
   ├── Multibinit/
   ├── TomASD/
   ├── Vampire/
   └── ESPInS/

The main human-readable file is ``exchange.out``.  It lists the magnetic
pairs, lattice-vector translation ``R``, isotropic exchange ``J_iso`` in meV,
the pair vector, and the pair distance.

Practical Notes
---------------

* Always report both the TBUpy SCF k-mesh and the TB2J exchange k-mesh.
  They control different parts of the workflow.
* Check whether the TBUpy solution is metallic or insulating before
  interpreting exchange constants physically.
* The exchange constants can be sensitive to ``U``, ``J``, the double-counting
  choice, and the converged orbital-polarized solution.
* Use denser TB2J k-meshes and larger ``nz`` values for production results.
  The values in the tables above are useful workflow checks, not final
  convergence studies.
